# 交付物格式规则（三类报告通用，最重要）

三件套交付物的形式必须**严格一致**。一致性由 `templates/` 的 docx + `scripts/` 的构建脚本钉死，务必复用。

## 0. 每次审核第一步：问询姓名
启动审核**先问**本次「审核人姓名」「批注人姓名」（可相同），确认审核日期（默认当天）。**勿假设默认值**。
- 审核人姓名 → 审核意见信息表「审核人」单元格。
- 批注人姓名 → 批注版 Word 批注的 `w:author` / `w:initials`。

## 0.3 ⭐交付目录与送审文件夹隔离（用户定，每单必须照此）

- **送审文件夹只读**：不得在其中写入任何文件（txt 抽取、表格 dump、截图、临时脚本一概不写）。
- 在送审文件夹**同级**新建交付目录 `审核-<项目号>-<项目简称>\`，根目录只放交付成品：
  - `资产评估报告_批注版_<项目号>.docx`、`资产评估说明_批注版_<项目号>.docx`（房地产/土地为单一批注版）
  - `交叉验证报告--<项目号>-<项目简称>.docx`
  - `<项目号>-<项目简称>-三级审核意见-<审核人>.docx`（第二批）；二审另有落实核查表同放此处
- 一切中间件放子目录 `审核-<项目号>-<项目简称>\_审核工作文件（勿外发）\`：抽取的 txt、Excel dump、PDF 抽图、照片缩略图、`ann_*.json`/`cv.json`/`cfg_opinion.json` 等配置、临时脚本、续做说明。
- 范例：送审 `2026AAP0297-归类·报审\` → 交付 `审核-2026AAP0297-华电金川废旧物资\`（含 `_审核工作文件（勿外发）\`）。
- 读取：`extract.py <文件> --out "<交付目录>\_审核工作文件（勿外发）"`（脚本已改为不写回源文件夹，写回时会报 WARN）。

## 0.5 ⭐交付顺序：两批交付，中间夹一道"人工介入审核"（2026-08-25 用户定）

三件套**不是一次性全交**，而是分两批，中间必须停下来等人工：

```
第一批交付 ──►  ① 批注版报告（+ 评估说明批注版）   ② 交叉验证分析报告
                        │
                        ▼
              停下来问："审核意见是否明确？"       ← **必须停，等用户回答**
                        │
              人工在 Word 里增删改批注（删掉不认可的 / 改写措辞 / 补新问题）
                        │  用户答"明确"
                        ▼
第二批交付 ──►  ③ 审核意见 docx ＝ 回读**当下批注实况** + 明细表/测算表意见
```

- **第一批交付时不得生成审核意见文档**。审核意见是人工确认后的产物。
- 提问用**普通对话文字**（例："批注版和交叉验证已出，请查看并直接在批注版里调整批注——**审核意见是否明确？**"），然后**停止等待**；不依赖弹窗/表单（跨平台会卡）。用户答"不明确/再看看"就继续等，**别抢跑**。
- **审核意见的唯一事实来源＝人工确认后 docx 里真实存在的批注 + Excel 类（评估明细表/测算表）意见**。**不得**照抄模型先前口头列的清单或前一版配置——人工删掉的条不能借尸还魂，人工改写的措辞必须以文档里的为准。
- 用户改完若**另存为新文件名**，回读必须用新文件。
- **序号两条路都不会断**：①成品用 **Word 自动编号**，在 Word 里直接删掉整条意见，后续序号自动重排；②脚本生成时也现场 1..N（删批注或用 `DROP` 剔条后重跑）。**任何情况下都不要手打/手改编号。**
- 回读还会自动处理三种"杂质"：**非本次批注人的批注**（承做人留在源文档里的旧批注，按 `AUTHORS` 白名单滤掉）、**Word 里标"已解决"的批注**（默认不计入）、**回复型子批注**（默认跳过，可 `REPLY_MODE=merge` 并入父条）。三者都会在控制台报数，便于核对。

## 1. 审核范围与批注版份数
- 审核对象 = 报告 + 评估说明（仅资产评估有）+ 评估明细表 + 测算表（用「位置」字段区分来源）。
- **⛔评估说明"第二部分 关于进行资产评估有关事项的说明"不提意见**（该部分由委托人/管理人及产权持有人撰写，正文通常仅一句"此部分由管理人及产权持有人撰写，具体内容详见附件"）。该部分**已有单独的线下审核**，本技能的审核意见与批注**一律不涉及**：不提撰写主体、不提内容缺失、不提附件未见、不提未签章。注：若报告其他部分引用该说明中的数据并与正文矛盾，仍按勾稽一致性照常提出。
- **测算表/明细表只审"非隐藏"的 sheet**：隐藏/极隐藏（hidden/veryHidden）工作表不审、不提意见（`extract.py` 已自动跳过）。
- **批注版（Word 真批注）**：
  - 资产评估报告：报告、评估说明**各出一份**批注版。
  - 房地产估价 / 土地估价：通常单一文档（结果报告+技术报告在一个 doc），出**一份**。
  - 测算表/明细表是 Excel，不做 Word 批注；其意见写入「审核意见」文档。
- 每条批注**直接描述问题**，**不要**加 `[重大]/[一般]/[提示]` 等等级前缀；**只描述问题，不写依据条款、不写整改建议**。
- **依据条款 / 整改建议不进交付物，但要留在脑子里**：用户在对话中**具体问某条意见的依据条款或整改意见时，单独口头告知**（即时回答，不写回成品文档）。所以审核时仍须搞清每条问题的依据与整改方向，只是不落进批注/审核意见。
- 同一段落可挂多条批注（多个 commentRangeStart/End 共用一段；注入时按段分组，勿用"整段已用"去重挡掉同段第二条）。

### 2.2 逐条问题块（v2 定式）
每一大类首条前加一行**加粗**类别提示（"资产评估报告："/"评估说明："/"评估明细表："/"评估测算表："…），**无意见的大类不输出**。每条固定：
```
1、                          ← **Word 自动编号**（脚本注入 numbering.xml；序号段本身是空文本）
位置：<报告章节/材料>        ← "位置："加粗，内容常规
原文：<引用原文>             ← "原文："加粗，内容常规
审核意见：                   ← 加粗，标签独占一行
　　<意见正文，只描述问题>    ← 另起段·首行缩进 2 字符(firstLine 480 / firstLineChars 200)
回复：                       ← 加粗；**该段带段落下边框**
                             ← 空段，**也带段落下边框**
                             ← 空段（不带边框）；**全篇最后一条不留这个空段**
```
- **序号＝Word 自动编号**（`N、`，顿号非冒号），跨大类连续 1..N。v2 模板不带 numbering.xml，由 `build_opinion.py` 注入编号部件（numFmt=decimal、lvlText=`%1、`、suff=nothing、仿宋_GB2312 12pt、左缩进 0），序号段为空文本。**在 Word 里直接删掉整条意见，后续序号自动重排；改配置重跑脚本也现场 1..N。禁止手打序号。**（2026-08-25 用户要求：此前字面序号在 Word 里删条会断号。）
- **条目尾部固定三段**：`回复：`[下边框] + 空段[下边框] + 空段（无边框）；**最后一条省去第三段**。（2026-08-13 用户二次调模板后定版：早前一度改为只留一条边框，现已恢复为两段都带边框。）
- 正文字号统一 12pt(sz24)，字体 仿宋_GB2312 / Times New Roman，两端对齐，行距 1.5(360)。
- 位置、原文允许留空（该行不输出）；审核意见正文含 `\n` 时自动拆成多个缩进段。
- **按文档大类分组排序**：顺序固定 资产评估报告 → 评估说明 → 评估明细表 → 评估测算表（房地产/土地：报告 → 测算表）。**每一大类首条意见前加一行加粗类别提示**（"资产评估报告："/"评估说明："/"评估明细表："/"评估测算表："/"土地估价报告："等）；无内容的大类不加。跨doc勾稽问题归入更靠前的大类。
- **⭐大类内按"批注顺序"排列**：报告（及评估说明）大类内的各条意见，须**按批注版报告中批注出现的先后顺序**（即报告正文位置由前到后：封面/致函/特别提示→假设→结果报告→技术报告→测算过程…）排列，与批注版逐条对应，**不要按问题类型/严重程度另排**。报告、说明大类排完后，再列评估明细表、评估测算表意见。（Excel 明细表/测算表无 Word 批注，其意见按表内位置先后排。）
- **不放进此文档**：总体结论、数值复算表、清单待补项（数值复算归交叉验证；其余留质控内部）。

### 2.3 生成方式（**唯一合规做法**）

**默认走"回读批注"（新流程，人工确认批注后）**：用 Write 工具写 UTF-8 的 `配置.json`，再
`python scripts/build_opinion_from_annotated.py 配置.json`（加 `--preview` 可先只看清单不产文件）。键名：
`PROJECT_NAME/PROJECT_NO/REVIEWER/REVIEW_DATE/SECOND_REVIEWER/REPLIER/REPLY_DATE/OUTPUT`（同下）＋
- `SOURCES`：`[{"LABEL":"资产评估报告：","DOCX":"…批注版.docx","AUTHORS":["<批注人姓名>"],"POSITION_FALLBACK":"资产评估报告正文"}, …]`
  —— **按数组顺序即为大类顺序**（报告 → 说明）；`AUTHORS` 强烈建议填，滤掉承做人旧批注。
  「位置」自动取批注所在的章节标题（识别"第X章／一、／（一）／1.1"及 Heading 样式，两级拼接），无标题时用 `POSITION_FALLBACK`；「原文」取批注锚定范围内的原文（默认截 60 字加"……"，`MAX_QUOTE:0` 为不截断）；「审核意见」＝批注正文原样。
- `EXTRA_GROUPS`：`[["评估明细表：",[[位置,原文,意见],…]], ["评估测算表：",[…]]]` —— Excel 类无 Word 批注，手工给，排在 `SOURCES` 之后。
- `DROP`：可选，整数按上一次 preview 的序号剔条、字符串按意见正文子串剔条；**剔完自动重排序号**。
- `MAX_QUOTE` / `REPLY_MODE`(skip|merge|separate) / `INCLUDE_DONE` / `DUMP_JSON`（落盘合并后的 build_opinion 配置，便于人工再微调文字后直接重跑 `build_opinion.py`）。

**底层仍是 `build_opinion.py`**（格式与自检的唯一出处，回读脚本只负责"从哪拿内容"）。无批注版可回读时（如纯 Excel 类意见、或复用历史配置）直接用它：
`python scripts/build_opinion.py 配置.json`。键名：
`PROJECT_NAME`(项目名，不含书名号) / `PROJECT_NO` / `REVIEWER` / `REVIEW_DATE` / `SECOND_REVIEWER` / `REPLIER` / `REPLY_DATE` / `OUTPUT` / `GROUPS`。
`GROUPS = [[类别提示, [[位置, 原文, 审核意见], …]], …]`；旧配置的 `TITLE="对《X》审核意见"` 仍可用（自动提取项目名）。
脚本收尾会**强制自检**：XML 合法 / 四处占位符（`[项目名称] [项目编号] [审核人] [审核日期]`）已替换 / **标题第2行单独成段且只出现1次** / 挂自动编号的序号段数＝意见条数且正文无字面序号 / `回复：` 段数＝意见条数 / **正文表内下边框段＝2N** / 信息表已写入 / 三张表完整——任一不过直接报错退出，**不产出"看起来对"的错文档**。见到 `[FAIL]` 别绕过，先查模板是否被改动。

**模板换版时脚本要跟着改什么**（2026-08-13 两次换版的教训）：①标题两行现由模板自带，脚本只替换 `[项目名称]`，**若脚本仍自行拆段会多出一行标题**；②信息表值单元格的格式取自占位符 run 的 `rPr`（脚本自动沿用），模板改字号字体时无需动脚本；③条目尾部段数/边框由 `item_block()` 决定，改模板后须用「结构回归」核对（见下）。

**结构回归做法**：用 python-docx 把模板与成品各自摊平成「段落序列＋是否带下边框＋是否首行缩进＋首个 run 是否加粗＋标签名」的四元组列表，逐项比对模板骨架与成品每一条的重复单元，正文表外的 BODY 段序列须完全相等。

**成品基线**：本仓库**不放基线成品文件**（含真实客户信息，且本仓库有公开远程）。基线成品保存在**本机审核工作目录**下、由质控人指定的那一份"逐段核过的定版"。改脚本后按上述「结构回归」做法与该文件逐段比对即可。

## 3. 批注版（Word 真批注，从零注入）
做法（docx = zip）：
1. 在 `word/document.xml` 中定位批注锚点（按关键词匹配所在 `<w:p>` 段落），插入 `<w:commentRangeStart w:id="K"/>`（在 `</w:pPr>` 后或段首）和段尾 `<w:commentRangeEnd w:id="K"/><w:r><w:commentReference w:id="K"/></w:r>`。
2. 新建 `word/comments.xml`：`<w:comment w:id="K" w:author="批注人姓名" w:date="..." w:initials="...">…</w:comment>`。
3. `[Content_Types].xml` 加 Override：`/word/comments.xml` → `application/vnd.openxmlformats-officedocument.wordprocessingml.comments+xml`。
4. `word/_rels/document.xml.rels` 加关系：Type `.../relationships/comments` Target `comments.xml`。
（脚本 `build_annotated.py` 已封装。）

## 4. 交叉验证分析报告（套 `templates/crossvalidation-template.docx`）
- 标题 `交叉验证分析报告`(加粗sz32居中) + 副标题 `<项目名>（<项目号>）`(sz28居中)。仿宋_GB2312。
- 四节：
  - **一、数据对比表**：5 列(验证维度 | 报告取值 | 第三方/印证数据 | 偏差/勾稽 | 数据来源)，TableGrid，5列×1729dxa，表头加粗居中。
  - **二、数据对比可视化**：图1/图2（居中题注 sz24 + 内嵌 PNG 柱状图，约 5.51×3.07 inch）。
  - **三、分析说明**：【数据一致性核查】+【数据来源说明】两个加粗小标题，各带编号条目，首行缩进420。
  - **四、验证结论**：【验证结论】加粗 + 编号风险点 + 综合判断。
- **数据来源 URL 必须做成可点击超链接**：用 `<w:hyperlink r:id="rIdN">` 包裹 URL run(蓝色 `color 0563C1` + 下划线)，并在 `word/_rels/document.xml.rels` 加 `relationships/hyperlink Target="URL" TargetMode="External"`。**不要写成纯文本。**
- 方法：抽结论值/参数 → 内部分项复算勾稽 → 联网取第三方市场数据算偏离度 → 可视化。
- **取数只取相关、非隐藏数据**：交叉验证的报告取值/参数**一律取自报告正文、评估说明和非隐藏的测算/明细 sheet**；隐藏/极隐藏 sheet、与本次评估对象/价值时点无关的数据**不取、不入对比表、不参与勾稽**（`extract.py` 已自动跳过隐藏 sheet）。
- **⭐"第三方/印证数据"列必须是独立第三方公开来源**（中介挂牌/成交平台、政府或行业公布价、公开招租/拍卖公告等），**严禁用本评估项目自身的可比案例价/询价记录/测算表取数充当**（自证无效）；项目自带案例价只能放"报告取值"一侧。**独立第三方数据找不到就在该格如实写"未找到/找不到"，绝不编造、不得用项目案例价顶替**。
- **第三方验证同一对象尽量多找几个来源/可比**（不强制，市场活跃可多、不活跃可少）；**搜不到如实反馈、绝不编造**；按面积段/楼层/区位/业态/容积率匹配可比（教训：单一来源易偏颇；土地按容积率级差比较）。
- 图表：matplotlib + 中文字体(如 SimHei，`axes.unicode_minus=False`)生成 PNG；嵌入法=复制模板 docx，替换 `word/media/image1.png`/`image2.png`，保留 drawing 的 rId9/rId10。

## 5. 通用注意
- 老 .doc 不可读 → 请对方转 .docx；扫描 PDF → OCR 或请对方提供可读版/口述关键信息。
- 覆盖写入 docx 前注意可能被 Word 锁定（PermissionError）→ 脚本含 try/except，锁定时另存"（已修订）"版并提示关闭后重开。
- docx 操作走 zipfile + XML 直接重写最稳（python-docx 旧版无 add_comment）。
